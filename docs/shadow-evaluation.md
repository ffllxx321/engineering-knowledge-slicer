# 生产影子评估

`v2.13` 提供插件内、本地优先、默认关闭的质量/成本/时延观测基础。它复用生产解析和知识工作流，但候选卡只用于计数与质量检查，不进入卡片、MOC、索引或正常任务终态。

## 安全边界

- 设置中的“启用影子评估”与用户点击运行共同构成启动条件。
- `shadowProviderBudget=0` 时，远程文档解析和 AI 请求均为硬拒绝；PDF/旧 Office 需要云解析时返回类型化审核原因。
- 大于 0 的预算只适用于 MiniMax 结构阶段，每次真实请求先扣预算；解析外传在影子模式仍保持关闭，避免批量评估扩大上传范围。
- 复用正常 artifact 前先校验既有输入指纹；新产生的影子 artifact 使用 `shadow-` 前缀，不覆盖正常检查点。
- 取消通过独立 `AbortController` 传播；每完成一份文档就保存有限账本，下次运行可继续命中检查点。

## 指标与隐私

报告 schema 为 `eks-shadow-evaluation/1.0`，账本为 `eks-shadow-store/1.0`。来源仅记录加盐 SHA-256 伪名；报告不记录源哈希、文件名、完整路径、正文、引文、凭证、prompt 或 provider 响应。

文档级指标覆盖来源类型、parser、粗粒度语言、字节数/大小桶、解析块/eligible 块、定位与证据核验率、分类 route/confidence、总结覆盖、原子/候选卡/审核数、重复/重生成与类型化原因、缓存命中、阶段耗时，以及可得的请求/token/成本计数。聚合使用分子/分母重新计算比率。

保留同时受 `shadowRetentionDays` 和 `shadowSampleLimit` 限制。代表队列不读取内容或文件名，按任务元数据中的类型、parser、大小桶、语言分层，再用固定 seed 对稳定来源哈希排序并轮询抽样。

## 基线与提升

“保存当前基线”冻结聚合指标、插件和 pipeline 版本；后续报告按相同字段输出 delta，因此输入和有效检查点未变化时无需重跑已完成阶段。

当前版本不支持从影子结果直接提升到生产写入。要入库必须回到正常任务显式处理；这避免影子运行意外改变终态，并让提升语义保持清晰。

## 本地报告

Dashboard 的“影子评估”页或命令面板可导出 JSON / Markdown。导出使用系统保存对话框和权限 `0600`，只写用户选择的本地文件。
