# 通用企业知识管线（v2.20）

## 为什么重构

旧生产路径同时存在“分类—总结—原子—卡片”、Phase 1/2/3、表格增强和两库 writer。解析结果先被旧流程制成卡片，再反向包装为 Phase 2 候选；文档只有一个库和目录路由。这样既混合了物理解析与知识决策，也无法正确处理一份资料中的项目事实和通用方法。

v2.20 建立唯一的结构化生产路径：

`格式适配器 → 统一文档块 → 多标签画像 → 语义区域 → 知识单元 → 标签/两库/关系 → 四类记录 → 完整写入计划 → 事务提交`

旧 artifact 仍可读取，但在进入新路径、恢复、缓存命中和迁移边界都会规范为统一知识单元；旧 schema 不再决定新知识的切分和路由。

### v2.20.1 生产边界修正

`structured-pilot` 和 `structured-write` 不加载或执行旧卡片 workflow，也不调用 Phase 2 候选管线或 Phase 3 审核门。writer 的完整生产输入固定为 canonical document、universal result、项目登记表、ID→路径索引、现有文件与设置。旧 Phase 2/3 实现仅用于显式 legacy、旧 artifact 迁移/读取、回滚和兼容测试。

通用模式每次都写入带 `semantic_path: universal` 的审核视图；其中只包含统一管线的分组决定、关系问题和 writer 冲突。旧 `workflow.review`、`hardRejected`、计数、路由与 artifact 不参与计划、任务终态、遥测或界面聚合。

### v2.20.2 通用语言层

语言属于 canonical block 和语义区域，而不是文件格式或整份文档的单一属性。每个区域记录 `zh/ja/en/mixed/unknown`、置信度与汉字、假名、拉丁字母计数。中日英业务表达先归一为同一语义类型、主题、标签、路由信号和关系依据，再规划知识单元。

最终标题、陈述、摘要、标签、路由说明、审核原因/动作和 Markdown 正文固定为简体中文。中文区域直接进入规划且不产生翻译调用；日文、英文和混合知识区域先尝试安全词典渲染，其余使用现有 MiniMax 文本提供商按区域批量翻译。页眉页脚等非知识噪声不翻译。

翻译缓存键由规范化区域正文、源语言、`zh-CN`、翻译 prompt 版本和当前模型组成。请求只接受严格 `translations[{region_id, translated_text}]`，必须与请求 ID 完整一一对应，并保留名称、组织、项目/合同/招标编号、标准、材料/产品/型号、数字、日期和单位以及义务强度、条件和例外。批次失败时保存已完成缓存和缺失 ID，重试只补缺失区域；不得回退为日英 Markdown。

知识单元同时保存 `original_*`、`translated_*`、源/输出语言和翻译状态、来源、版本。稳定指纹使用源语义区域与证据身份，因此译文改写或模型升级不会制造重复记录。Markdown 明确分开“来源证据（原文）”和可选“证据中文译文”，定位与 provenance 始终属于逐字原文。

## 决策边界

- 格式适配器只恢复顺序、标题、段落、列表、表格、页/工作表、邮件、附件和原文定位。未知格式退化为 text block。
- 画像是多标签的，描述用途、领域、生命周期、项目/实体范围、时效、权威、保密和结构置信度。
- 区域边界来自标题层级、语义类型、范围、时间、布局和连续性，不按扩展名、页数或固定行数制卡。
- 知识单元按主题、范围、责任、状态和检索价值拆分；仅在相邻且兼容时合并。每个有意义区域必须 covered、merged 或带中文理由 dropped。
- 数字、日期、单位和型号只在原文出现时提取；它们本身不会触发审核。

## 两库、标签和链接

在办项目事实、行动和当前投标过程进入在办投标库；通用方法、标准、模板、公司知识以及完成、暂停、取消、终止、归档项目材料进入长期业务库。同一文档可逐知识单元分流。项目状态不明确时整份文档只产生一个归属决定。

标签使用“语义类型 + 业务领域 + 生命周期 + 项目/实体 + 质量/安全/成本/时间”等受控维度，同义词先归一，优先复用已有标签并限制数量。

关系只由显式共享身份、明确引用或有证据的兼容关系产生。记录 ID 与文件名、目录分离，ID→路径索引负责移动；双方均写关系，wikilink 使用稳定 ID，因此归档移动不破链。

## 写入与审核

仍使用四种标准记录：项目、来源文档、业务事项、公司知识。正文以中文为主，稳定 ID、类型和标签放在 YAML；原文定位显示为“第几页/工作表/区域/章节”，正常界面不展示 JSON。

writer 在修改 Vault 前生成完整计划，检查路径占用、重复 ID、乐观锁和动作上限。提交带事务清单；失败恢复原内容并把新文件移入可恢复隔离区。重跑按稳定 ID 和内容 hash 更新或 noop。

只有实质冲突、两库归属不明、不安全写入冲突和高影响关系歧义进入人工处理；同一根因按文档合并，并显示中文原因和具体动作。

## 成本与回退

普通路径使用结构信号、确定性哈希、受控词表和本地相似度。缓存键包含块/区域指纹、管线、prompt 和模型版本；覆盖修复只处理遗漏区域。LLM 的扩展点位于歧义区域和高价值决定，不重复处理全文。遥测记录块、区域、单元、覆盖率、压缩率、模型调用/令牌、缓存、审核、关系和写入。

用户只需配置来源/输出根、凭据和可选项目登记。高级切分阈值、内部 schema 和安全规则无需配置，也不能由组件包替换。组件包可以调整词汇、标签同义词和目录映射；缺少外部组件时内置同一管线继续运行。
