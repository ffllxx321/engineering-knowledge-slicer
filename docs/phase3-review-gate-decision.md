# 第三阶段：少确认的安全分流

第三阶段继续作为影子流程，不替换稳定切片和写入链路。三个开关
`phase3_shadow_enabled`、`phase3_pilot_enabled`、`phase3_write_enabled` 默认均关闭；
本阶段没有自动生产写入。

## 三种结果

- 自动通过：证据可定位，且没有下列硬风险。置信度不参与人工分流。
- 通过并提示：目录未确定、路由信息不完整或非关键差异。提示不阻塞后续试运行。
- 需要处理：只限项目归属冲突；金额、日期、单位或状态的关键矛盾；证据缺失或无法定位；
  模型添加来源未支持的事实；把项目资料提升为公司可复用知识。

人工项按“来源文档 + 可执行根因”合并。相同文档中相同缺证问题可一次处理；
关键事实冲突还按冲突身份分开，不能为了少报数量合并不同矛盾。

## 撤回与决策记录

文档级撤回函数只生成计划：将该文档影响的记录列出，留待未来受控写入阶段反向处理。
计划明确保留用户原文件和项目状态。决策记录采用只追加、前后相连且可校验的摘要链；
任何历史条目被改动都能被发现。

## 衡量目标

计数包括生成数、自动通过数、提示数、需处理数和问题组数。目标是正常条目不因低置信度
或统一门槛进入人工队列；硬风险召回由逐类确定性测试保障。通过率只报告实际数据，不预设
85%—95%。当前合成回归中 500 个正常条目实际自动通过 500 个，需处理 0 个；该数据仅证明
“不爆审”，不代表真实业务通过率。

## 重叠审计

Phase 3 是独立纯计算模块，没有从 `src/main.js` 或插件 bundle 注册命令、定时器、生产写入、
删除或审核队列。Phase 1/2 API 和请求上限、续跑、零供应商试跑保持不变。
